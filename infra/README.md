# Infrastructure and local development

- Docker/Compose are approved for local app/server and a portable production server image. Static frontend may deploy directly to Cloudflare Pages.
- Managed Supabase PostgreSQL/Auth and private Cloudflare R2 remain outside local production containers.
- OCI Always Free preferred backend host; Render a constrained fallback. Both require validation before use with real medical data.
- GitHub Actions is the preferred **external scheduler** for weekly backups; the backup script must remain independently runnable and include verification and missed-run alerts.
- Do not embed credentials or medical records in the repository, Docker layers, CI artifacts, GitHub logs, or example env files.
- Provider-independent encrypted archives with consistent DB/object manifest; 90-day rolling weekly retention; restore authorization/deletion reconciliation.

## Local implementation

`compose.yaml` runs only local PostgreSQL, migration tooling, and the API. Start it with `pnpm local:up`; see the repository [README](../README.md#local-api-and-database) for all commands. Credentials are generated by `scripts/local.mjs` into ignored private `.local/compose.env`; they are runtime environment values and are excluded from Git and the Docker build context. Never print full Compose configuration or store real medical records here.

The API runtime image uses a non-root user and contains compiled API code and production dependencies, not migration tooling. Local Compose additionally uses a read-only filesystem and drops Linux capabilities. PostgreSQL is reachable only on its Compose network. Production deployment remains unconfigured.

Prisma migrations and schema live in `apps/server/prisma/`; the baseline has no patient tables. The local database owner is reserved for migration tooling. The separate `fmv_app` runtime role cannot create objects, read the migration ledger or bypass RLS. Production roles and policies must be reviewed separately; see [approved decisions](../docs/architecture/decisions.md) and [open validations](../docs/architecture/open-decisions.md).

`pnpm test:db` builds local tooling and creates a uniquely named disposable Compose project. Its cleanup removes only that project's volume. `pnpm local:down` retains the development volume and credentials. Migrations are reviewed forward changes; never accept a Prisma reset prompt against retained data. Application tables, table grants, RLS policies and client generation belong to the P1 identity/authorization slice.

For final verification on this Mac with Postgres.app already installed, build the server and run `node infra/scripts/test-db-native.mjs`. It creates a private temporary cluster on a fresh loopback port with generated credentials, runs the same migration/security suite, then stops and removes only that cluster. It reads no project `.env` or cloud credentials and requires no Docker session. The test suite retains its fresh-database and endpoint/role fences.

Prisma PostgreSQL pools explicitly select UTC sessions, and raw timestamp writes use ISO timestamps with `timestamptz` casts. This avoids timezone-dependent adapter serialization affecting grant expiry, audit dates or rate limits. Validate UTC startup options on the hosted session-pooler connection before applying the new migrations; hosted verification remains separate from local tests.
