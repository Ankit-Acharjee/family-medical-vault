# MED-01/MED-02 — owner recording and correction interface

Delivered owner-only recording from current reviewed prescription blocks, explicit current/historical status, literal editable fields and a separate confirmation. Exact-source choices reuse their existing record ID/revision and retain owner corrections and immutable history; matching names across sources are never merged. Source attestation alone creates no medication record or schedule.

Owners can correct the recorded fields/status through a sibling dialog, and explicitly relink a newly reviewed version of the same prescription document after source/lifecycle invalidation. Relinking preserves the existing medication identity, recorded context and prior versions. Source changes never imply treatment stopped. Choices claimed by another record cannot be used to merge identities. Source discovery now orders by latest review time so reviewing an older document makes it discoverable within the existing bounded picker.

The interface reuses the existing protected resource/write hooks, Radix dialog, Input/Button primitives and semantic theme tokens. It preserves drafts and measured dialog height through same-context permission checks, clears protected forms on lost access, blocks dismissal while saving, seals uncertain operations for exact retry, and handles lost acknowledgements, validation failures and concurrent identity/revision conflicts. Confirmed success dismisses the dialog, refreshes the list and restores focus. Optional unknown fields remain null; status is never inferred from prescription wording.
