# MED-01/MED-02 — Meds browsing and preserved history

The existing Meds route now reads the deployed owner-recorded medication ledger. Recorded current/historical sections stay distinct, literal uncertainty and unknowns remain visible, and invalid source bindings require review without changing recorded treatment context. Details show all nine fields, source document/block/revision/fingerprint, recording time and collapsible preserved versions, with a separate always-current record. List/history controls use bounded server pagination.

Patient-wide View eligibility prevents document/category-only list requests. Failed or malformed data has an explicit retry state; denial clears visible data and revalidates patient access. Same-context focus refresh hides protected details while retaining the dialog identity and its measured height, and keyboard dismissal restores focus. No medication writes or source-field-to-current-status inference are introduced by this browsing slice. Browse-source actions open the existing Documents route; direct original comparison and owner recording/correction forms are the next slice.

Reused the established resource hook from manual-readings (via a local descriptive alias), semantic tokens, Lucide, shared Buttons and Radix Dialog. No global styling, Overview layout or dependencies changed. Actual axe checks found existing shared visible/accessibility-name mismatches; mobile labels now include their visible abbreviations and the patient label has an explicit separating space, preserving its accessible name. The inactive document-search placeholder is omitted only on Meds. Shell tests follow the corrected names and wait for existing finite CSS transitions before sampling contrast.

Validation: 45 frontend unit/proxy checks; 14 Meds browser checks plus 20 shell/Overview regressions across desktop/mobile; web typecheck/build, lint, formatting and secret checks passed. Includes source invalidation messaging, exact unknowns/history, list/history pagination, category-only denial with zero requests, failed/malformed responses, retry, focus revalidation, access loss, axe, reduced motion, 320px overflow and controls above mobile navigation. Actual synthetic screenshots were inspected at 1440×1000 and 390×844 in both themes. Existing Vite loader/chunk-size warnings remain; no performance optimization, device Safari/screen-reader certification or live hosted user-flow claim.
