# SUM-01 — in-app bounded patient summary

Delivered Patient summary from the existing Meds toolbar, including empty medication lists and authorized read-only delegates. The shared Radix dialog reads the source-authorized summary API and supports patient/laboratory/manual/medication scope and exact paired reported-date filters. Owner-confirmed labs preserve raw qualifiers/precision/unknown fields, undated results stay separate, manual values/offsets remain user-reported, and medication status is a labeled current record snapshot. Source/window limits are visible; the view does not claim complete history, infer diagnoses/treatment intervals or offer export/share/external processing.

Reused existing MeasurementDetails/OriginalComparison and MedicationSummary; moved the existing unchanged ReadingSummary into a small shared file instead of duplicating manual-value display. Lab source comparison uses its existing protected byte/fingerprint flow. Medication links open the existing session-protected original preview in a new tab with noreferrer; no public key/token is exposed. The readings action reaches the existing Trends route. Source/record provenance remains expandable and traceable. No Overview/global-theme/navigation refactor, dependencies or backend changes in this UI slice.

Filters retain drafts and dialog height through same-context access checks while protected records are hidden. Denial/context departure clears the summary; failed/malformed/mismatched patient/scope/period responses fail closed and offer explicit retry. Period equality compares fields, not JSON property order. Native collapsible filters keep records visible on initial mobile opening; raw provenance details remain available on demand. This density refinement followed actual screenshot inspection, without changing functional scope.
