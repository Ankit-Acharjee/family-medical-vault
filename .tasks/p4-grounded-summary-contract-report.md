# SUM-01 — bounded summary representation

The approved read authority and period semantics are recorded in canonical sharing/security documents. The pure contract/projector accepts already-authorized current lab/manual/medication read pages, verifies patient/source representation, preserves decimal/qualifier/unit/unknown fields and exact source references, separates undated labs and suppresses withdrawn manual/stale medication inputs. Periods use reported collection days and manual calendar days with original offsets retained. Medication current/historical labels stay an explicitly labeled current-record snapshot; no historical treatment interval or diagnosis is inferred. Output is independently copied and finite coverage limits remain explicit.

Six adversarial contract tests cover exact/reversed/impossible periods and strict request shapes; source/precision preservation and nonmutation; offset calendar-day versus UTC/recording dates; stale/withdrawn exclusion; all four scopes and actual full20-row cursor bounds; and wrong-patient/source/value/extra-field substitutions. Contracts build and repository types/lint pass. This is a pure representation foundation, not an authorization mechanism or a complete delivered summary UI/API. The next slice reuses guarded transaction-local readers under one patient/source authorization boundary. No schema, dependency, provider or hosted change.

Files: packages/contracts/src/grounded-summary.ts and index.ts; apps/server/test/grounded-summary.test.mjs; docs/domains/sharing.md; docs/security/access-control.md; task plan/report. Native workers remain quota-limited; supervisor implemented/reviewed with no OpenCode fallback or unavailable Astra signoff. No clinical records or secrets were used.
