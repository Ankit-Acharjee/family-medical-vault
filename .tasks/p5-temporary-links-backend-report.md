# SHARE-02 — owner-only temporary-link ledger foundation

## Scope and approved policy

Explicit owner-only creation/revocation, selected-originals-only bearer access without recipient account/passcode, mandatory owner-chosen expiry of1–168hours, permanent source lifecycle invalidation and no implicit whole-vault scope were approved by the user on18November. This delivery is the **backend ledger foundation**, not complete external sharing: there is no anonymous HTTP recipient route, byte-serving handler or link UI yet. No public record access is enabled by this slice.

## Implementation

Protected session/Origin/CSRF management endpoints prepare an exact owner-authorized selection, create one-time secrets, list bounded status/history and irrevocably revoke a link. The existing original-selection source guard is reused by a small extracted module export rather than introducing a new authorization store. Independent private original Export semantics remain intact. Creation pins the exact selection fingerprint and freezes source identities, object generations, hashes, MIME, sizes, titles and Trash/Restore lifecycle. A source/profile identity mismatch makes the link unavailable. Parent metadata is owner-protected, not a public category/patient query.

Secrets use existing32-byte cryptographic opaque values and a purpose-separated SHA-256 persisted lookup. No plaintext token is stored. The secret is returned only on first successful creation, never in list/revoke responses. The request ID and payload hash serialize creation retries across instances; matching replays return the same link with `token:null` rather than minting or pretending to recover a lost secret. Changed payloads conflict. Owner UI must support revoke/recreate when the one-time response is lost. A quota of20 unrevoked/unexpired links per patient bounds work; list returns all such outstanding links before bounded older history.

Migration `20261118000200_temporary_links` adds a private link ledger and separate ordinary anonymous-access event table. Both use FORCE RLS and narrow runtime column privileges. SQL guards enforce current owner, exact ready/active source snapshots, bounds,7-day expiry, immutable grant fields and one-way owner-attributed revocation. Access events have DB-controlled timestamps/90-day retention metadata, no token/IP/medical fields and no impersonated owner actor. An internal capability-inspection method checks current owner/source state, expiry and revocation, audits successful metadata access atomically and rechecks after audit; it has deliberately no HTTP route. Parent creation/revocation identity/time records are not claimed to implement future critical-event retention or deletion propagation.

No dependency, external processing or hosted write was introduced. The new Prisma models reflect both tables; existing migration-ledger expectations now cover27local migrations. Hosted migration27 needs separate approval.
