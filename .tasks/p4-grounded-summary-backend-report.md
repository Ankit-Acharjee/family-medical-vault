# SUM-01 — atomic in-app summary read

Added authenticated GET /api/patients/:patientId/summary with explicit patient/laboratory/manual/medication scope and paired exact fromDate/toDate calendar bounds. No-store and existing session/private-error boundaries apply. Current patient-wide View is required before any protected source read. A single canonical patient-access-locked transaction composes the existing lab workspace and manual/medication page readers, retains their source locks/freshness checks and value-free audit events, projects the approved bounded representation, then checks fresh aggregate and every included document's current ready/non-Trash View again before returning. Unknown failures remain sanitized. No persistence, provider, dependency, migration or hosted write.

The existing manual/medication list bodies are narrowly exposed as documented internal transaction-local readers; their ordinary list endpoints still acquire the same lock/transaction and call the unchanged read body. A whitespace-insensitive review confirmed query, authorization, ordering, bounds, audit and final checks are retained. The pure contract never establishes authority. Medication treatment dates are not inferred; period selection uses the approved reported laboratory/manual calendar days and preserves unknowns separately.
