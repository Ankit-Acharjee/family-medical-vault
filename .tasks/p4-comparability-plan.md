Proceed under the user's approved LAB-03 authority: cross-report comparability requires explicit profile-owner confirmation; source-field confirmation or literal matches never grant comparability automatically. Model foundation is defined in measurements.ts. This is implementation planning, not a completed feature or authorization for hosted writes.

- Inspect existing clinical confirmation/withdrawal history and scoped View patterns before defining the smallest immutable comparison-set ledger. Reference exact document, source SHA, saved-text revision, clinical review revision/candidate and lifecycle for every member; never copy a client claim as authoritative clinical data.
- Owner alone confirms/withdraws a set, under current View on all members. Reading membership or derived values requires current View on every disclosed member. - Preserve source/history. No silent fallback to an old set or automatic substitution after source updates; changes require explicit review of comparability again. Qualified/textual values and unknown dates remain distinguishable; plotting eligibility is a separate constraint from source verification.
- Reuse existing primitives and approved themes for a focused owner review flow; do not populate new features with invented measurements. Start with model/API lifecycle and tests before chart work, keeping dependencies and hosted migration approval gates explicit.

Native independent review is required before release; Astra if available, otherwise disclose the actual reviewer. No external models/providers or clinical advice.
