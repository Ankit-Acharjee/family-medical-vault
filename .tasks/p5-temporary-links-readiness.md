# SHARE-02 — temporary external links readiness

Next ready roadmap area after summary and selected-original ZIP exports. Canonical authority: `docs/domains/sharing.md`, `docs/domains/access.md`, `docs/security/access-control.md`, F-05 in UX flows and sharing screen specification. Existing caregiver invitation links are not anonymous document-share authorization and must remain separate.

A recipient link would confer access outside the authenticated caregiver grant workflow, so existing independent Export or Manage permissions cannot silently be interpreted as authority to grant it. Initial issuer/revoker authority remains a genuinely missing product decision. Ask whether only the explicit owner may create/revoke external temporary links initially, with delegate sharing deferred. Do not implement an implicit public-access grant before this decision.

Requirements to preserve in the eventual bounded implementation: explicit patient and exact selected sources, owner-chosen scope/expiry, revocation and access events, opaque high-entropy tokens stored only as hashes, no token/content in URLs logged by infrastructure or analytics, token confidentiality through recipient flow and referrer controls, current source/lifecycle validation on every access, no listing/enumeration and no long-lived provider URLs. Expired/revoked/source-invalid links stop future serving; downloaded bytes cannot be recalled. Keep private original and summary export semantics independent. Broader recipient verification, download permission, content scope, expiry bounds, token transport and abuse controls must be resolved against canonical specifications before exposing an anonymous endpoint.

Authorized independent groundwork: inspect existing access-link/token/session primitives and reusable source authorization/expiry/audit boundaries, document the threat model and design options. Do not enable a hosted public route, create real share tokens, expose records, or apply a migration based only on this readiness note. Any reviewed hosted migration/deployment retains its separate approval gate.
