# MED-04 — owner-only open-page reminders

Implemented the approved 18 November scope: explicit per-schedule opt-in, page-memory choices, generic in-page notices only, no medical details in notices, no background-delivery promise or per-dose confirmation. Closing the schedule dialog preserves intent while the current patient's Meds page remains open/visible. Route/patient/session departure and pagehide clear it; hidden/access-checking states pause and skip elapsed minutes. Stop controls remain available. No OS notification permission, service worker, external provider, persistent preference, dependency, schema or hosted write was introduced.

Only current owner-recorded medications with a current source-bound recorded clock schedule can enable a reminder. Literal, historical, retired, obsolete or delegate contexts remain informational. The schedule response now supplies authoritative medicationStatus after existing patient/document authorization. Every due occurrence reads that existing guarded endpoint again and rejects changed revisions, source, ownership/status or failed validation. Abort signals, object identity and generation fences prevent late work from rearming stopped intent. Saves and uncertain closes stop the old choice. This is an operational UI affordance, never clinical prescribing or dependable delivery.

Exact named-zone calendar-minute indexing counts candidates instead of normalizing missing/ambiguous times. Gaps/folds require review for the selected day; no earlier/later occurrence is chosen. Date windows/weekdays suppress notices; no conversion of prescription text or clinical dose fields occurs. Public timezone/day indices are bounded in memory and built cooperatively, cancelled when inactive. Chrome DevTools on an isolated blank synthetic page measured the initial240-iteration chunk at50.2ms; reducing to60 yielded a subsequent five-day index in584.8ms elapsed, max1.4ms synchronous chunk across121 chunks. This is a local microbenchmark, not a device-independent responsiveness or delivery guarantee.
