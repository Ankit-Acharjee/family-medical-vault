# LAB-04 manual readings — owner-only backend foundation

User approved owner-only creation/correction/withdrawal with preserved history on17 November2026. The canonical medical-data/security policy is updated. This slice adds the contract, immutable application-schema ledger and bounded API; the manual-entry interface is planned separately and is not claimed as delivered.

## Behavior and authority

- Exact string values, explicit selected units and the entered observation timestamp with an explicit UTC offset are stored as manual/user-reported data. BP has separate systolic/diastolic fields; weight, pulse and glucose have one value. No fabricated source document, laboratory verification, unit conversion, guessed timezone, diagnostic threshold or clinical-plausibility claim. Format bounds are not medical validation.
- Only the current explicit Person owner may write. Existing patient-scope View permits reading this patient-level data/history; category/document grants do not become patient-wide authority. The shared patient-access mutex, transaction-local PermissionService and final authoritative checks protect every operation, including expiry during audit. UUID case is canonicalized for locks; a separate reading mutex serializes identity collision/CAS. Client actor/provenance fields are rejected.
- Record/correction/withdrawal append immutable revisions; the runtime cannot update/delete them. Corrections replace the full entered payload while keeping the reading kind fixed. Correct a mistaken kind by withdrawing its identity and creating the intended reading. Withdrawal is terminal for that identity and keeps prior values visible in authorized history; it is not erasure or verified clinical data. Latest-request semantic retries reuse the exact expected revision and canonical payload; older/reused/conflicting requests fail without creating versions.
- Current-list keyset pages contain up to20 latest identities, including clearly marked withdrawals, sorted by most recent update; this is not an observation-time chart or snapshot across concurrent edits. A fresh list after changes resets pagination. History pages contain up to20 immutable versions with a separate always-current state, so old pages never activate historical data. All reads are audited atomically without values in event metadata or application logs.
- Migration21, `20261117000100_manual_readings`, adds only manual ledger/events, exact validators, owner/revision/transition/server-time guards and append-only SELECT/INSERT grants with FORCE RLS. Functions are invoker-only with PUBLIC execution revoked. Ordinary read events receive90-day expiry; the existing critical-retention/production cleanup decisions remain separate. Prisma models match the new relations. No external processing/provider or original-document lifecycle changes.
