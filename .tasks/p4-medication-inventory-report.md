# MED-03 — optional owner-reported inventory

Delivered optional quantity, expiry and refill information on existing medication records, using the explicitly approved owner-only write/history and medication-equivalent read policy. All three fields are bounded literal reports with null unknowns: preserve uncertain quantities, package wording and month-only expiry without inventing an exact date. There is no stock consumption, arithmetic, expiry classification, refill advice, reminder or treatment-status inference. Upload and reconciliation remain independent of inventory. Explicitly clearing all fields preserves earlier reports.

Each append-only inventory version binds to an exact medication reconciliation entry/revision. Medication/source changes do not silently re-confirm previous inventory: the UI shows the original medication revision and requires explicit review/save. New writes require the current reviewed source; owner-visible invalid-source history stays labeled. Existing reconciliation identity and current patient/document authorization remain authoritative. Reads require owner authority or patient-wide View plus source View; delegates cannot write. Current/latest and bounded immutable history stay distinct during pagination.

The backend reuses the existing medication service transaction, patient/medication/document locks, source projection and final permission recheck. The focused inventory store handles CAS, semantic exact retries and atomic value-free audit. Migration24 creates two new tables, FORCE RLS, append-only runtime privileges and owner/source/revision guards, without rewriting originals, medication entries, keys or grants. The shared contract reuses the existing literal validator without dummy clinical fields; JSON/DB validators preserve Unicode and unknown-value bounds.

The UI reuses Input/Button/Radix and the existing protected resource/write hooks. It supports owner create/correct/clear, delegate read-only history, pending dismissal protection, sealed uncertain retries, lost-acknowledgement checks, conflicts/reload, draft retention through same-context focus checks, access-loss removal and confirmed-success dismissal. Browser testing caught a detached-focus target after an unnecessary medication-list reload; removing that reload preserves focus and avoids replacing unchanged list content. The dialog identifies the patient and medication, scrolls at narrow widths and omits empty history controls. Overview and unrelated screens are unchanged.
