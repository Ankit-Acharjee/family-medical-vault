# P4 measurement discovery and owner comparison workflow

LAB-01/02/03, ACCESS-02/04/05 and UX-05/06. The existing Trends route now discovers current owner-verified laboratory entries, shows literal values/date/unit and original evidence, and lets the profile owner explicitly review, confirm, inspect, withdraw and reconfirm cross-report comparison sets. Current View delegates can read permitted results and whole permitted sets; matching labels never create a set automatically. No chart, conversions, inferred reference interval or medical advice is supplied by this slice.

## Implementation and review

- Added one bounded workspace GET under the existing patient-access mutex and transaction-local permission service. SQL filters current View scopes before caps (25 recent original documents/50 results and 10 latest set summaries, with authorized sentinels); all participating originals are locked deterministically before fresh clinical/source metadata is read. No full extraction texts are loaded. Current source/clinical/lifecycle references, final authority and atomic read audit are checked. Denied resources do not contribute counts or limit flags. Immutable ledger/schema are unchanged.
- Strict shared response guards bind each option to one patient, exact document/candidate/review/source/SHA/lifecycle tuple, current source descriptor and literal result/date classification. Per-set result guards reject mismatched provenance and mixed patients. Output caps are explicit; discovery is not an exhaustive history or a promise of constant query cost for very large patient ledgers.
- Reused semantic tokens, Inter/Lucide, Button/Input/ResourceState/Radix Dialog and original-preview hash checks. Selection is limited to 2–20 entries across multiple documents. Unknown specimen/method remains explicit; incompatible known fields and units cannot be combined. Local filters and clinical data are not persisted to URLs/storage.
- Same-context selection and exact pending request identity survive focus revalidation while protected content is hidden. Changed patient/session or access clears content; changed source requires explicit fresh review. Writes refresh CSRF, use CAS/idempotency, never retry automatically and require acknowledgement tied to exact references/revision. Pending dialog cannot dismiss; uncertain retry reuses its exact body; successful save dismisses, refreshes and restores focus. Read/submit deadlines and malformed-response failures have actionable recovery.
- Browser review found an existing global patient-dialog exit could briefly mount the upload form after the dialog kind became null, causing unintended document/category fetches. A narrow `dialog === 'upload'` render guard fixes this without changing routes, styling or upload behavior. Dialog adds an optional backwards-compatible disabled close control used only for pending comparisons.
