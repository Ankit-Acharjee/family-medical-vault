# DEL-03 / BACKUP-04 — isolated link delivery and receipt drill

Extends the actual disposable PostgreSQL recovery drill with a source-intent-to-receiver flow. The helper verifies the connected PostgreSQL data_directory resolves to the harness's ephemeral cluster before touching fixtures. It deliberately removes one local synthetic capture, repairs it from the retained revoked link and verifies exact patient/resource/time binding and stable retry identity.

The actual canonical single-event evidence is age-encrypted using a generated ephemeral identity. A separate database in the disposable cluster atomically persists ciphertext plus an Ed25519-signed, domain-separated receipt binding event UUID, ledger ID, digest, size and receiver sequence. After commit but before acknowledgement, the test disconnects, reloads the event-named staged ciphertext file, reconnects and gets the same persisted receipt. Changed ciphertext, wrong signing key, altered receipt and absent signature namespace are rejected. Receiver sequence allocations may have gaps and are never treated as a coverage anchor.

Native28 plus the complete encrypted database/original/evidence/publication drill passed. Infra44, lint, secret detection, formatting and diff checks pass. Native Sol implemented only the test helper; Astra reviewed isolation, replay and bounded claims; supervisor integrated and verified it. Initial review caught insufficient cluster binding and memory-only replay; both corrected before release. A pagination-copy formatting issue from the prior UI slice was corrected without changing behavior.

This is an isolated test receiver, not B2 or another independently hosted ledger. The public verification flags keep independentlyHostedLedgerVerified=false and sourceLossCoverageVerified=false. Generated keys/files and the cluster are removed after the test. No real credentials, hosted writes, provider key creation, source cleanup, completion upgrade, scheduler or automatic restore reopening is enabled.

Next integration gates remain stable durable production ciphertext staging, dedicated ledger signing trust/custody, constrained provider producer credentials, independently observed receipt/version binding and source-loss coverage/fencing. Existing Read Only B2 credentials cannot publish. Local intent/outbox existence, a per-event receipt and a terminal metadata cursor cannot establish global restore safety.
