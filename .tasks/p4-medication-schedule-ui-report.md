# MED-04 — informational schedule interface

Delivered owner recording, correction, explicit source re-review and retirement from the existing Meds route. Users preserve literal/uncertain timing or explicitly choose weekdays, named timezone and clock times; dates and instructions remain optional. Nothing parses prescription frequency into a schedule or changes medication treatment status. Delegates receive authorized read-only timing/history. Retirement preserves timing/history, including when the source needs review, and later source review never silently records it again.

The interface reuses existing semantic tokens, Input/Button/Radix components and protected resource/write hooks. It handles empty/loading/denied/recoverable failure, literal/clock validation, weekday/time limits and removal, pending dismissal protection, exact uncertain retries, lost acknowledgements, CAS/source changes, preserved same-context clock drafts/modal height, access-loss clearing, confirmed-success dismissal and focus restoration. Latest/current stays authoritative while history pages change. No unchanged medication-list reload is introduced after schedule saves.

Schedule context now includes the authoritative current medication name after server-side authorization. The dialog uses that fresh label instead of an older parent-list label when a medication revision changes. This narrowly extends the new schedule read contract; inventory's API and behavior remain unchanged. Browser checks caught helper text entering accessible field names; helpers now use descriptions outside concise labels.
