## Safety and lifecycle

- Only the profile owner may confirm/withdraw, with current View on all members. Delegates need current View on every member to read a set; no partial membership or denied counts are returned. Patient access locks, transaction-local authoritative permission snapshots and sorted document locks serialize grant changes and source operations. Mixed-case UUIDs use the same canonical access-lock key. The shared transaction-access implementation was extracted from the caregiver service without changing its authorization rules.
- Latest event only, with expected revision/CAS, canonical reference hashing and latest-only semantic retry. Any changed source SHA, extraction/review revision, candidate, lifecycle, Trash or clinical withdrawal prevents the entire set from supplying measurements. No old confirmation fallback. Owner withdrawal retains the binding/history and can revoke while originals are in Trash, without returning their clinical contents.
- Exact analyte and non-null unit literals are required. Conflicting known specimen/method literals are rejected; unknown stays unknown and requires the explicit owner decision. No conversions, normalization, guessed fields, abnormality assessment or treatment advice. Exact numeric/qualified/text and original date/evidence representations remain intact.
- New migration20 adds only the comparison ledger, exact source links, restricted functions/triggers and two audit-event kinds. Ledger/source links are runtime SELECT/INSERT-only with FORCE RLS. Deferred checks prevent incomplete source linkage. Privileged source-link deletion removes the whole set history; existing original-retention/audit/object-generation FKs remain intact. Their physical purge workflow belongs to P6 and is NOT implemented or bypassed by this feature. No SECURITY DEFINER or runtime DELETE privilege was added.
